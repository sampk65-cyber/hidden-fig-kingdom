# V15.10 — 一個人的武林

The first catalog entry uses the supplied recording from 01:04.160 to 02:04.160: sixty decoded seconds, stereo MP3 at 96 kbps. Acoustic onset timestamps were generated from the encoded excerpt, with three deterministic difficulty charts and 2.6 seconds of preparation before the first target. These are automatic acoustic accents; no physical-device listening calibration is claimed.

The three harvest pads share one success timbre. Only ripe Perfect/Good hits sound. Every four consecutive correct hits raises the pitch by one semitone, capped at five steps; NG resets the combo. Existing hit windows, points, green-fruit penalty, reward conversion and result callback are preserved.

Recording loading is cached and retryable. Closing, changing song or changing practice difficulty during loading invalidates the pending start. Recording playback uses the existing audio clock and owns its sources, pause/resume and cleanup. Cold-muted starts can join the current position when sound is enabled.

## Scope and checks

- Only formal `index.html`, the added audio asset, rhythm tests and rhythm documentation changed. `test.html`, backend, weather, greenhouse art, Firebase rules/paths and all other game source remain unchanged.
- The twelve original song objects and all 36 original chart outputs match V15.9 exactly.
- `node --test docs/*regression.cjs`: 16 top-level tests passed, including legacy touch/weather/header/greenhouse suites and encoded-duration/sample-count/audio-energy validation.
- Managed Chromium with actual production rhythm code and Web Audio: shared lane tone (about 883 Hz at the same combo tier), Perfect/Good scoring, NG/green silence, combo reset, success-tail cleanup, 60-second decode, playback offset, pause/resume, mute/unmute, quit, retry, cold-muted recovery, delayed-start cancellation and delayed-preview cancellation passed. The difficulty-loading race is covered by an explicit failing-before-fix browser test.
- Asset verification found a 128 kbps candidate truncated to 49.118 seconds at a file boundary. The final 96 kbps asset is 720,734 bytes, retains exactly sixty decoded seconds, and passes verification after subsequent filesystem/tool boundaries. A regression now checks encoded duration and exact decoded sample count.
- Independent read-only review found the asset truncation and practice-loading difficulty mismatch. Both were reproduced and fixed; no other significant code blocker was reported. Browser/device hearing, deployment and backend integration were outside that review; deployment is verified separately after publication, and the backend is unchanged.
