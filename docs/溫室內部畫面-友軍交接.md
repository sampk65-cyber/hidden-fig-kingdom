**圖的規格**
- 單棵樹、正面平視、**透明背景**，WebP 格式，每張 150 KB 以內。
- 直式，寬不超過 512 px、高不超過 768 px。
- **樹幹底部碰地的點，放在圖片下緣正中央**。圖的四周不要留空白，程式會把圖的最上緣當作樹頂。

- 有變化圖（`-2`、`-3`），程式就會自動輪流使用；沒有就只用主圖。
- 任何一張載不到，程式會自動改回原本的樹，畫面不會壞掉。
- Claude 收到後會先確認只有 `art/gh/` 裡的圖檔有變動，再上測試版，確認後才上正式版。

## 1. 目標

把「走進溫室巡園」的立體畫面，做成接近參考圖的寫實插畫風格：

- 參考圖：`docs/ref/溫室內部參考.jpg`
- 想要的感覺：
  - 透明玻璃拱頂與藍天
  - 兩側成排的無花果樹（大葉、果實清楚）
  - 淺色水泥走道與黑色塑膠布植床
  - 陽光從左上方灑下，地面有葉影斑駁
- **走動、遠近縮放、藏寶光束、樹搖晃、落葉、點樹找寶箱**這些現有效果，全部都要保留。

## 2. 工作方式（請嚴格遵守）

1. **開分支**：`git checkout -b gh-art`。只推到 `gh-art`，**不要推 main**。
2. **只改 `test.html`**，不要改 `index.html`。
   - 兩個檔案的程式完全一樣，差別只在 Firebase 設定。
   - test.html 是示範模式，資料只存在本機，改壞了也不影響玩家。
   - 合併時由 Claude 同步到 index.html。
3. 新素材放在 `art/gh/` 資料夾。
4. 完成後，在本文件最後的「友軍回報」寫下：改了哪些函式、新增哪些檔案、已知問題。然後推上 `gh-art`。

## 3. 程式在哪裡

整個遊戲是單一檔案 `test.html`。以下用函式名稱搜尋：

| 函式 | 作用 | 可以改嗎 |
|---|---|---|
| `drawFigTree(cx, pj, x, z, s, stage, seed, rustle)` | 畫一棵無花果樹，兩個溫室場景共用 | ✅ **主要改這裡** |
| `stageTree(stage)` | 各階段樹的高度與果實設定 | ⚠️ 可讀；改 `h` 會影響點擊範圍，盡量不改 |
| `openGH3D(zid)` 裡面的 `frame()` | 一般溫室的立體巡園：天空、拱頂、地面、植床、走道、樹、角色 | ✅ 只改「畫背景、地面、拱頂、光影」的部分 |
| `openEmerald()` 裡面的 `frame()` | 翡翠溫室（另一套場景，也呼叫 `drawFigTree`） | ✅ 同上 |
| `palm()` | 畫葉子的小工具 | ✅ |

### 投影與座標（看懂就能畫）

- `pj(x, y, z)` 把 3D 座標轉成螢幕座標，回傳 `{x, y, s}`。
  - `s` 是那個距離的縮放比，代表 1 公尺幾個像素。
  - 回傳 `null` 代表在鏡頭後面，不用畫。
- 單位是公尺：`x` 是左右（排的位置），`y` 是高度，`z` 是往前的深度。
- 樹的底部是 `pj(x, 0, z)`，樹頂是 `pj(x, stageTree(stage).h, z)`。
  - 圖片要從樹底往上畫，寬度依 `s` 縮放。
- `stage` 是 `'剪枝' | '座果' | '採收' | '度冬'`。
  - 度冬沿用剪枝的圖，可以調暗或去掉新芽。
- `rustle` 是藏寶樹在附近時的搖晃量，大約 -0.35 到 0.35。可以用來旋轉或斜切樹冠。
- `seed` 是每棵樹固定的亂數，可以用來挑不同變化的圖，或決定左右翻轉。

## 4. 絕對不能動的東西

- **點擊判定**：`G.hit.push(...)`、`G.nearHit`、`cv.onpointerdown`。
  - 樹的位置與高度必須維持，否則玩家會點不到樹。
- **藏寶樹**：`TRE`、`ghTreasures()`、`tapTree()`，以及光束的判斷條件。
  - 光束的**外觀**可以美化，但出現的條件不能改。
- **玩家資料與後端**：`P.*`、`DB.*`、`API.*`、`Auth.*`、`/api/game`、Firestore 規則。
- **其他頁面**：地圖 `renderMap`、首頁、券夾、後台。
- **畫面上的文字**：「點我找找 ▼」、已找過的結果標記、上方位置與能量列。
  - 可以美化樣式，但要保留，並保持清楚可讀。

## 5. 素材規格

| 檔案 | 內容 |
|---|---|
| `art/gh/fig-prune.webp` | 剪枝：主幹加短枝，少量新芽 |
| `art/gh/fig-set.webp` | 座果：枝葉茂盛，掛小顆綠果 |
| `art/gh/fig-ripe.webp` | 採收：枝葉茂盛，掛熟紫紅果 |
| `art/gh/roof.webp`（選用） | 玻璃拱頂加藍天的遠景，可從參考圖上半部裁切 |
| `art/gh/ground.webp`（選用） | 走道或植床的材質 |

**所有素材**
- 去背（透明背景），WebP 格式。
- 每張 **150 KB 以內**。

**樹的圖**
- 直式，寬不超過 512 px、高不超過 768 px。
- 樹幹底部碰地的點，放在**圖片下緣正中央**，方便對齊 `pj(x,0,z)`。
- 每個階段可以多準備 2～3 種變化，用 `seed` 輪流使用，避免整排長得一模一樣。

## 6. 實作建議

1. **預先載入圖片**，例如 `const GH_ART = {prune:new Image(), …}`。
   - 圖片還沒載好、或載入失敗時，**退回原本程式畫的樹**，畫面不能空白。
2. 在 `drawFigTree` 開頭判斷：有圖就 `cx.drawImage(...)`，沒圖就走原本的程式。
3. **效能**：中階 Android 手機要維持順暢，大約 50～60 fps。
   - 很遠的樹（`s` 很小）可以用小一號的圖，或簡化成一團色塊。
   - 不要每一格畫面重新建立漸層或 Path2D，能先算好的就先算好。
   - 地面葉影可以預先畫在一張離屏 canvas 上，每格只貼一次。
4. **光線**：陽光從左上方來，樹的陰影往右下落在植床上。
5. **夜晚**（選用）：19:00 到 05:00 可以讓拱頂外變夜空、溫室內亮暖黃燈。
   - 可以參考地圖用的 `skyTone()`。

## 7. 怎麼測試

1. 用手機或桌機瀏覽器打開 `test.html`。
   - 本機要用 http 伺服器開啟，例如 `npx serve`，用 `file://` 可能讀不到圖。
2. 按「🧪 產生一盒測試 QR，直接進入」，選角色、填暱稱，進入王國。
3. 點地圖上任一溫室，再按「走進溫室巡園」。
   - 至少測**一般溫室**（例如晨曦）和**翡翠溫室**各一次。
4. 檢查以下各項：
   - [ ] 搖桿前後左右走，樹的遠近大小正確，樹底貼地、不漂浮。
   - [ ] 藏寶樹有光束、會搖晃、會落葉。
   - [ ] 走近點「點我找找」能開寶箱；找過的樹會顯示結果。
   - [ ] 三個階段（剪枝、座果、採收）的樹都正確。
     - 可以在 test.html 的管理後台調整溫室階段，或直接改 `ZONES[i].stage` 測試。
   - [ ] 手機上順暢、不卡頓。
   - [ ] 圖片載入失敗時，會退回原本程式畫的樹。
